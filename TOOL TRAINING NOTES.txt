CODELISTS: -
============
-->In RCC, The Pre-defined values are called as Code lists.
-->In Instruments, go to code lists tab and create code lists by providing the item label and item code.
-->Once the code list is done then add it to the instrument variable.
-->There two types of codelists they are:
      1)Master Code list:-
             -->The Master code list is a comprehensive list that contains all the terms/Codes of a particular data element.
      2)Subset Code list:-
             -->The subset code list is derived from master code list that contains only the specific data element codes/Terms.
             -->Unique subset code list and Linked Subset Code list.


Steps for creating Instruments,codelists, event definitions and data entry: -
============================================================================
-->First Go to created study.
-->Go to instrument field and enter instrument name(mdes_form_name), instrument title and description.

-->while creating the variables we need to follow the sequence and check for mde_is_required as "YES".
-->Now go and creat the study event defintion.

-->Now we can go to subjects feild and enter the sites and subject number and then we can enter the data.
-->Save and exit that's all.


TYPES OF FORMS/INSTRUMENTS:-
-----------------------------
-->Flat forms(eg:-SV001,DM001)
-->Repeating Forms(eg:-AE001)
-->Forms with repeating logs/sections
-->forms with fixed repeating logs/sections

Flat Forms:-
------------
-->It is a single Level form where each field can appear only once for a visit or subject with no repetition.
-->ex:- demographic forms

Repeating forms:-
-----------------
-->A form that can be entered multiple times for the same (visit or subject) to capture the repeated Actions.
-->example:- adverse events forms

Forms with Repeating Sections:-
-------------------------------
-->A single form that contains a group of fields that can repeat within the form.
-->Ex:- concomitent medications

Forms with Fixed Repeating Sections:-
-------------------------------------
-->A form that contains a fixed number of repeating sections.
-->Ex:- Vital signs forms


EVENT DEFINITIONS:-
====================
-->Event is nothing but a Visit.(i.e On what Particular date or day that we need to attend the Clinical Trial)
-->we are having some of the events like:
     1)Static Event-->It is mandatory event to add it to the Study/Subject level.
                   -->It does not require any kind of dynamic condition.
     2)Scheduled Event-->To Add this event to the Study/subject level we need particular dynamic condition.
     3)Unscheduled Event-->We can add this event to the study/Subject level whenever we required.
     4)Parent Event
     5)child Event-->under parent event we need to add this child event and we can add many child events under parent.
        -->We can add forms only inside the child event

-->Components:-
   ----------
      -->Event title, Description, Day Schedule, Max Repeating allowed, Day MIN, Day MAX, Unique event title, Category,Active

-->If we are making any form as Repeating then one separate label will be populated that is nothing but "Custom Instrument Label".

PRE_DEFINED FUNCTIONS IN EXPRESSION BUILDER(RCC):-
=================================================
1)"abs()":- 
     -->Return the absolute Value of a Number.
     -->Eg:- abs(arg), abs(-4)=4

2)allobjects():-
      -->Return an Array with the Provided Value.
      -->Eg:- allobjects(arg1)

3)array_values():-
     -->Extract value from the elements in the provided Array.
     -->Eg:-  array_values(field,subject|event|instrument)
     -->By default the scope is subject.

4)not():-
    -->It is going to return the boolean value based on the field we provide.
    -->eg:- not(true)=false
            not(false)=true

5)empty():-
    -->Returns true if the provided value (or) array is empty otherwise false.
    -->eg:- empty(654736)=false
            empty([])=true
            empty("")=true

6)completed():-
    -->Returns true if the given array size is greater than zero otherwise return false.
    -->Eg:- completed([1,2,3])=true

7)concatdlm():-
    -->concatenate the given values by using the provided delimiter.
    -->eg:- concatdlm(separator,feild1,field2,field3,..)
            concatdlm("-","one","two")=one-two

8)contains():-
    -->Rerutns true if the provided value contains the second value otherwise return false.
    -->Eg:- contains("abc","bc") = true

9)count():-
    -->Return the Number of elements in the array.
    -->Eg:- count([1,2,3])=3

10)count_values():-
    -->The function counts the number of repetitions of the value in the second argument into an array of values of the first argument.
    -->eg:- count_values(array_values(field),target value)

11)dateadd():-
    -->add or subtract from the date.
    -->eg:- dateadd(date,units,quantity,dateformat(YYYY-MM_DD))

12)datediff():-
    -->Caluculate difference between the dates or times by using the datediff() function.
    -->eg:- datediff(date1,date2,units,returnsignedvalue,decimalvalues)
             units:- weeks,days,months,hours,minutes,seconds

13)startswith():-
     -->Returns true if the first string starts with the second String otherwise return false.
     -->Eg:- startWith("ABCD","AB")

14)endsWith():-
     -->Returns true if the first String ends with the second String otherwise return false.
     -->Eg:- endsWith("ABCD","CD");

15)functions._comparedates():-
      -->compare two dates, if two dates are equal then it will return "0".
      -->If First date is before the Second date then it will return "-1".
      -->If first date is after the second date then it will return "+1".
      -->It will compare only the dates not with time.
      -->Eg:- functions._comparedates(date1,date2)

16)functions._getdatedifference():-
      -->Return dates difference between two dates in a specific range.
      -->Eg:- functions._comparedates(date1,date2,"MINUTES"|"HOURS");

17)equals():-
      -->Return true if both the objects are equal.

18)hasall():-
     -->This function compares all elements from the collection are equal to the second argument.
     -->Eg:- hasall([3,3,3])=true

19)hasany():-
     -->This function checks if the first argument(collection) contains the second argument.
     -->eg:- hasany([1,2,3],30)=true.

20)min():-
     -->Return minimum element from the provided array.
     -->Eg:- min([1,2,3])=1

21)max():-
     -->Return maximum element from the provided array.
     -->Eg:-max([1,2,3])=3

22)mean():-
     -->Return avg of the provided array.
     -->Eg:- mean([1,2,3])=2

23)sum():-
     -->Return sum of the elements from the Provided array.
     -->sum([1,2,3])=6.

24)sqrt():-
     -->Returns the perfect positive square root of a number.
     -->sqrt(16)=4

25)indexOf():-
     -->This function returns the index value of a element in an array.
     -->Eg:- indexOf("Dolo",["citrozen","Dolo","Paracetmol"])=1
    
26)lenght():-
     -->This function returns length of the provided object.
     -->Eg:- length([1,2,3])=3

27)todecimal() and todouble():-
     -->Returns double value of provided argument.
     -->Eg:- todecimal("2.23")=2.23

28)toint32():-
     -->Returns long value of the provided argument.
    
29)toString():-
     -->return string value of the provided argument.
 
30)isnumeric():-
     -->returns true if the provided argument is numeric.

31)toupper():-
     -->convert all the lower case characters to the upper case characters.

32)dateextract(date,units):-
     -->This Methods extracts Months or years or days or minutues or hours from the given date.
     -->Eg:-dateextract("2026-06-03", "d")
     units:- weeks,days,months,hours,minutes,seconds

33)hourunknown(arg1):-
     -->This Function Returns "true" if the Hour fragment is entered as Unknown.
     -->eg:- hourunknown("UNK:UNK")=true , hourunknown("UNK:12")=true

34)minuteunknown(arg1):-
     -->This Function Returns "true" if the minute fragment is entered as Unknown.
     -->eg:- minuteunknown("12:UNK")=true

35)dayUnknown(arg1):-
     -->This Function Returns "true" if the day fragment is entered as Unknown.
     -->eg:- dayUnknown("2026-03-UNK")=true

36)monthUnknown(arg1):-
     -->This Function Returns "true" if the month fragment is entered as unknown.
     -->eg:- monthUnknown("2026-UNK-12")=true

37)elementat(arg1,arg2):-
     -->This Function Returns element placed at the Provided Position
     -->Eg:- elementat([1,2,3],1)=2

38)dataseries(arg1,arg2,arg3,..):-
      -->This Function Returns the provided array without Null Values.
      -->dataseries([1,2,3,null,4,null,5])=[1,2,3,4,5]

39)selected(array_values,arg1):-

DYNAMIC EXPRESSIONS: -
=====================
-->Dynamic Expressions are used to trigger the events (or) instruments based on certain conditions.
-->There are three types of Dynamic Expressions in RCC they are:
    -->Create Dependent Event
    -->Create Dynamic Event
    -->Add Instrument
-->"Create Dependent Event" is used to trigger the parent and child events based on certain Conditions.
-->"Create Dynamic Event" is used to trigger the Events based on certain Conditions.
-->"Add Instrument" is used to trigger the "n" number of instruments into a particular event or "n" different events based on a certain condition.

      -->In Rules,
            Action TYpe:-
                   -->create dependent Event
                   -->Create Dynamic Event
                   -->Add Instrument

STUDY VERSION AND MIGRATION PLANS: -
====================================
Study Version:-
---------------
-->After Creating the study version and deploying in to DEV and again if we make any changes to the study or package then whatever the updates we have done those will be visible to new subjects dev but not visible to Old Subjects.

Format For Creating Study Versions:
------------------------------------
V<major version><minor version><Revision>
  Ex:- V.2.1.0

Major Version:-
---------------
-->Major Version needs to be increased only when deploying to UAT and only if the change that is being implemented in that study version does involves CRF changes. 

Minor Version:-
---------------
-->Minor Version needs to be increased only when deploying to UAT and only if the change that is being implemented in that study version does not involve CRF changes.

Revision Version:-
------------------
-->The study version revision number need to be increased by one every time during our development process we need a version to deploy to Dev.
-->Note that revision number needs to be dropped when deploying to UAT.(V5.2)

Migration Plan:-
----------------
-->If we are deploying our Package with the help of migration then whatever the updates we have done to the study version those will be visible to both 
   new subject and old subjects in dev as well.
-->We need to use the Migration Plan after Round 1 UAT only.

Format for Creating Migration Plan:-
------------------------------------
--->If our target Instance is DEV then create,
     MP<latest Study version in DEV> to <new study Version>

-->If our target Instance is UAT the create,
     MP<latest study version in DEV> to <new Study Version>
     MP<latest study version in UAT> to <new study version>
     MP<latest study version in PROD>to <new study version>
